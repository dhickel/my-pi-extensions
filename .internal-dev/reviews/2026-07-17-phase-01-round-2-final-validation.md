# Phase 01 Round 2 Final Validation

## Scope

Independent read-only validation of Phase 01 after repair round 2. Inspected the accepted plan records, applicable internal-dev guides and specifications, `sprint-planner` source, tests, prompts, state handling, publication helpers, and the installed orchestration skill. Ran the package suite and focused adversarial scripts for malformed retries, canonical paths, estimate detection, scope parsing, collisions, post-publication mutation, and replacement races. No source files were edited.

## Findings

1. **REPAIR — standalone and full publication are not failure-atomic or ownership-safe.** `runStandaloneAdvancePlan` publishes the plan before exclusively creating the review. A preexisting review collision reported failure while leaving the newly published plan. A post-publish injected structural entry reported failure while leaving both plan and review. `publishDirectoryAtomically` can replace an empty target directory created by another actor after its precheck; the inode race reproduced. In the full sprint, an injected post-publication entry left `planning/` and `reviews/advanced-plan-review.md`, marked the final phase checkpoint completed, and resumed with zero worker calls into the same failure.
2. **REPAIR — semantic validation is not inside every owning retry boundary.** The persistent concepts correction and non-final phase corrections complete before aggregate plan validation; a malformed concepts correction poisoned its completed checkpoint, caused the final phase to exhaust retries, and remained skipped on resume. Standalone draft, concepts, and phase semantics are validated only after their calls return, so malformed-first/valid-second outputs receive no second call. The orchestration-specific retry repair is correct, but it does not cover the full concepts → orchestration → phase sequence.
3. **REPAIR — estimate detection remains incomplete and over-broad.** The detector strips all code and only examines colon labels at line starts. It accepted common prose, Markdown tables, bulleted labels, dash/equality labels, number-word and range prose, engineer-day prose, and target/due/completion/deadline prose. It also accepted human estimates in code while rejecting legitimate non-date fields such as `Target: sprint-planner/validation.ts`, `Completion: all exit criteria pass`, and `Time: O(n)`. Corrective review files and corrected handoffs are not deterministically checked; a standalone corrected handoff containing a duration was published.
4. **REPAIR — scope-marker parsing is still nonexact and does not fully model Markdown fences.** It accepted `**Size**:small`, multiple spaces after the colon, lowercase `## scope size`, and markers inside unclosed backtick or tilde fences. Closed backtick/tilde fences, inline code, and indented code were excluded as intended.
5. **REPAIR — deterministic orchestration validation does not enforce the orchestration contract beyond headings, scope marker, and budget.** An orchestration with no dependency graph or waves, wrong models/multiple implementers, no PASS gate, and skipped integration passed `validatePlanFiles`. Prompts state the correct tuples and behavior, but malformed corrected output can still publish.
6. **Confirmed fixed or sound:** flat `concepts.md` + `orchestration.md` + contiguous phase shape and 2–3/3–5/6–10 budgets; cohesive one-agent/head-down/selective-example prompt guidance; exact model routes and orchestration skill scheduling language; corrected orchestration retries in persistent and standalone flows; canonical padded paths through full and standalone engine assembly; ordinary preexisting plan collision; one-winner behavior for two ordinary concurrent publishers; removal of `advancedReviewPrompt`; state constant v3 and rejection of older state.

## Risk Assessment

The publication defects can leave artifacts from workflows reported as failed and can replace another actor's empty target. Retry-boundary defects make malformed corrected concepts or earlier phases unrecoverable through ordinary resume. Estimate and scope parsing defects allow prohibited artifacts to pass deterministic gates. The orchestration content gap allows structurally headed but operationally invalid scheduling metadata to publish. State v3 is not coherent under poisoned component checkpoints or post-publication structural failures.

## Recommendations

- Validate each draft and corrected component, including review and corrected handoff output, inside its own persistent `#step` consume or standalone `#standaloneCall` callback before any write or checkpoint completion. Revalidate completed v3 component artifacts on resume and invalidate the first semantically bad step plus downstream work.
- Replace label-only estimate matching with Markdown-aware detection for common labels, prose, tables, bullets, word numbers/ranges, engineer-day forms, and date language. Exempt only legitimate machine timeout/TTL/retry/backoff/polling/cache/retention/lease semantics rather than all code, and avoid rejecting file targets, completion criteria, or complexity notation.
- Parse Markdown code state, including unclosed and variable-length fences, and require literal marker-line equality in an exactly named `## Scope Size` section.
- Add deterministic orchestration checks for every phase ledger entry, valid dependencies/waves, exact tuples, one implementer per phase, the review-and-repair PASS gate, and final integration.
- Stage and validate both standalone outputs before visibility. Reserve/create the review exclusively before plan publication or use an equivalent paired transaction; on failure remove only artifacts whose ownership/hash/inode is still proven. Use a no-replace plan publication strategy and remove fallible structural checks after commit, or provide ownership-safe rollback. Apply equivalent ownership/checkpoint rules to full-sprint publication.
- Add the focused adversarial cases from this review to the repository suite; the current publication-order tests check only successful existence and do not exercise collision or rollback behavior.
